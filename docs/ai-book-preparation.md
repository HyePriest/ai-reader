# ai reader · 给 AI 的书籍制作要求

优先在电脑上的 AI 工具里处理文件，再把一个 UTF-8 JSON 导入手机。输入可以是 EPUB、TXT、Markdown、Word 或可提取文字的 PDF；扫描文件需先 OCR 并校对。手机仍只需导入整理后的 JSON，不必支持每一种原始格式。

格式标识继续使用 `englishreader.book.v1`，以兼容已有文件。中等长度书籍一次制作、一次导入；长书可分章节处理，但不能用节选冒充完整书籍。后续增量导入沿用已有入口，暂不扩展流程。

## 可复制的提示词：英文原文 + 已有中文译本

请读取我提供的英文原文和中文译本，制作 ai reader 能直接导入的 UTF-8 JSON 文件，format 为 englishreader.book.v1，language 为 en。你的主要任务是提取、匹配、填入和校验，不是重新翻译已有译文。注释只收录所提供译本中实际存在的注释，不自行编写、补充或扩展解释。不要凭记忆复述原书。

1. 实际读取两份文件的正文、目录与章节顺序。以英文为正文基准，保留英文标题、章节和段落顺序。一个原文自然段对应一个 paragraphs 项，不能跨段合并或随意拆成多个自然段。忽略重复页眉、页脚和页码；有歧义或 OCR 错误时在交付说明中指出，不能猜改。
2. en 必须由程序从英文原文提取，保留单词、大小写、引号和标点；只允许规范化连续空白。中文 zh 优先逐字取自所提供译本，保留译者措辞和标点，不润色、不换译名、不把原译文混入自己编写的解释。
3. 先判断章节对应，再按语义匹配句段。允许一对多、多对一；不能只按句子数量或长度机械配对。中文语序调整时，选择足以保持完整对应的最小英文范围，不重复填入同一份译文。
4. sentences 项是阅读时点击查看译文的单元，不一定是语法上的整句。通常以 8–25 个英文词为参考；超过约 35 词时优先检查能否按分号、从句或自然意义边界拆分。数字不是硬上限：短对话保持完整，固定搭配不拆，不能牺牲意思或对应准确性。不得把整段或整章为了省事塞进一个单元。
5. 每个单元的 en 和 zh 要完整对应。不能为了缩短英文而随意切中文；确实不可自然分开的原译文允许保留较长单元，并在交付说明列出过长单元的位置与原因。禁止无标记地重译已存在的中文。
6. 发现缺译时，先搜索邻近段落和其他章节，确认不是语序变化、章节划分不同或尚未定位。确定中文译本删去或遗漏的英文，由你结合上下文补译，translation_source 填 ai；取自现成译本的填 published。补译沿用已有译名。不要把“AI 补译”等标签写进 zh 正文本身。
7. 一个单元不能混用未标明的原译文与补译；尽量在二者交界处分开。无法可靠定位、版本矛盾或尚未处理的单元保留完整 en，zh 为 null，在交付说明列出原因，不能强行猜配。完整提取译本已有的脚注、尾注、章末注和编者注，追踪注号、脚注链接或回链，找到其所注的中文词句，再通过中英对应关系关联到英文单元或段落，放入 annotations。注释 text 逐字保留译本的完整措辞和标点，只修复提取造成的断行、断词及明确的 OCR 错误；不概括、不改写、不删减，也不自行补充典故、背景或词义。每条注释必须用 quote 精确定位所注的英文单词或最短完整词组，不得省略 quote，也不得用整句或整段代替可定位的词语。quote 重复时用 occurrence 指定从 1 开始的出现次数。正文中的脚注引用标记不当作正文或译文内容。annotations 只写 quote、必要时的 occurrence、text；不写 title、source，不写“随书注释”“原注 id10”、文件路径、注号或来源标签。原注号与来源如需核查，只放在文件外交付说明中。找不到注释全文、对应正文或来源存疑时，在交付说明列出原注号、原位置及问题，不猜配、不编写替代注释。没有正文对应的前言、增补等也单独列入交付说明。
8. 每章 id 在全书唯一；每段 id 在章内唯一（如 ch1、p1）。不要使用 @title 作为段落 id。保留全书全部英文，即使只完成部分匹配；不能把示例或节选当作全书。
9. 用程序校验：每段各 en 用一个空格连接后，与原段落规范化空白并剥离脚注引用标记后的正文完全相同；章节、段落无遗漏、重复、重排；所有 id 合法且唯一；JSON 能解析；published 译文和每条注释全文确实来自所给中文文件；同一译文或同一条原注没有错误重复使用。对照译本逐条核查注号、注释全文及关联位置，报告译本注释总数、已收录数、未能定位数和存疑处，不能静默丢弃未配上的注释。同时报告总章节、总段落、已配原译本、AI 补译、未匹配单元和过长单元的数量及位置。
10. 实际交付一个 UTF-8 .json 文件，不生成网页，不在文件里放 Markdown 围栏或说明。交付说明放在文件外；说明处理范围、校验结果和版本问题。不要把 API 密钥或对话指令写入书籍。

格式示例（示例不能替代实际原书；注释中的【】是待替换占位说明，只有译本确有对应注释时才填写，否则省略 annotations）：

```json
{
  "format": "englishreader.book.v1",
  "language": "en",
  "title": "Rain",
  "author": "Example author",
  "chapters": [{
    "id": "ch1",
    "title": "Chapter One",
    "paragraphs": [{
      "id": "p1",
      "sentences": [
        {"en": "The rain stopped.", "zh": "雨停了。", "translation_source": "published", "annotations": [{"quote": "rain", "text": "【逐字填入译本中对应注释的全文】"}]},
        {"en": "She went home.", "zh": "她回家了。", "translation_source": "ai"},
        {"en": "The room was quiet.", "zh": null}
      ]
    }]
  }]
}
```

## 可复制的提示词：只有英文原文，由 AI 翻译

请读取我提供的英文原书，由你结合上下文翻译为中文，并制作 ai reader 可直接导入的 UTF-8 JSON 文件。无需我另外寻找中文译本；不要等待或要求提供译本。format 为 englishreader.book.v1，language 为 en。实际读取文件，不凭记忆复述原书。

1. 提取完整正文、章节和自然段，保留章节与段落顺序、单词、大小写、引号和标点；只允许规范化连续空白。忽略重复页眉、页脚和页码。OCR 或版本有疑问的地方在交付说明中指出，不猜改原文。
2. 每个原文自然段对应一个 paragraphs 项。sentences 是阅读时点击查看译文的单元，通常参考 8–25 个英文词；超过约 35 词时检查能否按自然意义边界拆分。不能为凑字数拆开固定搭配或完整短对话，也不要把整段或整章塞进一个单元。允许一个单元包含多个短句。
3. 先理解所在章节的上下文，再翻译各单元。zh 应准确、自然，保留人物语气、叙述风格和语义歧义；统一人名、地名和术语，不删减难句，不概述，不把解释扩写进译文。不能仅逐词拼接，也不能为了文采改变原意。
4. 每个非空 zh 均标记 translation_source 为 ai；不能冒充出版译本。无法可靠翻译或暂未完成时保留完整 en、zh 为 null，在交付说明中列出位置与原因。不要把“AI 翻译”等标签写进 zh。
5. 此方式只让你翻译正文，不让你创作注释。没有提供中文译本或真实注释材料时，省略 annotations 或设为 []，不要自行生成词义、典故、背景、情节解释，也不要凭记忆补出某译本的注释。若用户另外提供了译本注释材料，只逐字提取其中已有注释并关联正文，用 quote 精确关联所注词语，不填写 title 或 source；原注号和可核实的出处放在文件外交付说明中。无法可靠关联的列入交付说明，不猜配。英文原书中的脚注、尾注应与正文分开识别并在交付说明中列出，不把它们误作正文或冒充译本注释。
6. 每章 id 全书唯一，每段 id 章内唯一，不使用 @title。每段各 en 用一个空格连接后，必须与原段规范化空白后的文本完全相同。用程序检查章节、段落无遗漏、重复、重排，JSON 可解析，ID 唯一，en/zh 对应完整，全部译文已标为 ai，注释锚点有效。
7. 实际交付一个 UTF-8 .json 文件，不生成网页，不在文件内放 Markdown 围栏或说明。长书可以分批处理，但最终文件必须保留全部原文；未处理部分 zh 为 null，不能以节选冒充全书。文件外报告章节、段落、AI 已译单元、未译单元、注释数量，以及过长单元和存疑处的位置。

格式示例（以实际原书替换示例内容）：

```json
{
  "format": "englishreader.book.v1",
  "language": "en",
  "title": "Rain",
  "author": "Example author",
  "chapters": [{
    "id": "ch1",
    "title": "Chapter One",
    "paragraphs": [{
      "id": "p1",
      "sentences": [
        {"en": "The rain stopped.", "zh": "雨停了。", "translation_source": "ai"},
        {"en": "She broke the ice with a smile.", "zh": "她用一个微笑打破了僵局。", "translation_source": "ai"}
      ]
    }]
  }]
}
```

## 纯中文书

请把我提供的中文书整理为 ai reader 的 UTF-8 JSON。只提取、校对提取结果和整理结构，不改写正文，不翻译。保留章节、标题、自然段和标点。书中已有的脚注、尾注、章末注逐字提取到 annotations，通过原注号或链接关联所注词句，每条用 quote 精确定位所注的中文词语；重复时填写 occurrence。不写 title、source、原注号、注释类别、路径或来源标签；这些核查信息仅放在文件外。不自行编写注释。正文中的脚注引用标记与注释全文分开整理。无已有注释时省略 annotations，不能填入自己的解释。无法定位的原注在文件外逐条报告。使用下面的结构，并逐段校验正文完整、逐条核对注释。text 是中文原文，不需要 sentences 或 zh 字段。示例中【】内为占位说明，须替换成书内实际注释，无对应注释则省略该数组。

```json
{
  "format": "englishreader.book.v1",
  "language": "zh",
  "title": "雨",
  "author": "示例作者",
  "chapters": [{
    "id": "ch1",
    "title": "第一章",
    "paragraphs": [{"id": "p1", "text": "雨停了。她回家了。", "annotations": [{"quote": "雨", "text": "【逐字填入书中对应注释的全文】"}]}]
  }]
}
```

中文 TXT、HTML、EPUB 也可直接导入。复杂图表和特殊版式不在正文 JSON 的保真范围内。AI 补译标签用于提示来源，不代表翻译一定正确。

## 注释格式（适用于以上所有方式）

- 注释内容来自用户提供的译本（纯中文书则来自该书）中实际存在的注释。agent 负责提取、对应和校验，不生成注释；不能把 AI 自行解释改标为“译者注”或“原书注”。不因认为注释不必要或含有后文信息而擅自改写或删减原注。
- annotations 是可省略的数组，无原注时省略或传 []。每条新注释只使用 quote、text，以及重复匹配时的 occurrence。英文书优先放在对应 sentences 项；跨单元的词组可放在 paragraphs 项，仍须提供精确 quote。中文书放在 paragraphs 项。旧文件的 title、source 和无 quote 注释仍兼容读取，但不显示标题与来源；旧注释缺少精确锚点时仍只能定位到原来保存的范围末尾。
- text 必填，只保存原注的解释正文与标点，可用 JSON 的 \n 保留段落。去掉注号、链接标识、“原注”“随书注释”、版本信息和来源栏等外壳；注释正文内部有实际解释作用的引用、书名和出处仍保留。不得概括、润色、删减解释正文，不得添加自己的解释。
- quote 对新制文件必填，必须逐字匹配所在单元的 en，或所在段落的正文，不能填中文译文来定位英文。英文段落由各 en 去除首尾空白后用一个空格连接。优先选择所注的单词或最短完整词组；仅当原注确实解释整句时才使用整句，不能因定位困难而退回整段。
- 必须先追踪译本脚注引用或回链，确定注号所指的中文词语，再按中英对应找到英文 quote。quote 在文本中存在只是必要条件，还要核实它确实是这条注释解释的对象。不能把脚注所在页面、文件尾部位置或段落顺序当作注释锚点。找不到准确对象时，不写这条 annotations，在文件外交付说明列出原注号、位置和原因，禁止猜配。
- quote 重复时必须用整数 occurrence 指定第几次，从 1 开始，如 {"quote":"rain","occurrence":2,"text":"【对应原注解释正文】"}。匹配区分大小写和标点。无需计算字符下标，正文不要插入注释编号。阅读器在所注词句末尾显示小号上角标，点击后只显示注释正文，配色跟随主题，点击弹框外关闭。
- 校验每条 quote 确实存在，重复时 occurrence 有效，text 与来源材料中的原注一致；不得把占位说明当成真实注释交付。核对脚注或尾注数量、原注号和关联位置，缺失或存疑的逐条报告；不要在 zh 混入注释，也不要把注释当正文或正文翻译。
- 给已导入的 JSON 书补注时，保留原来的书名、章节 ID、章节标题、段落 ID、正文和完整结构，只增加或修改 annotations，然后重新选择书籍文件导入。软件会提示更新注释：替换此次提供注释的段落里的全部旧注释，其余段落、已有译文和阅读进度保留。若某段只想改一条，也必须带回该段所有要保留的注释。省略 annotations 或传 [] 都表示保留已有注释，不能用来清空；此流程不用于更新译文或导入删减过的书。
